# 02.1 · 데이터 모델 & 상태 머신 (v1 — 최신 모델은 02.4)

## 1\. 데이터 모델

```haskell
users
  id, email, display_name, role(USER|ORG_ADMIN), org_id?, residence_sido, residence_sigungu

intents                                    -- 대화 세션 1건
  id, user_id, track(DONATION|WILL|ESTATE)
  status(ACTIVE|PAUSED|EXTRACTED|CLOSED)
  transcript(jsonb), created_at, updated_at

intent_facts                               -- IE 추출 결과
  id, intent_id, key, value(jsonb)
  confidence(float), source_span(text)
  confirmed_by_user(bool)                  -- FR-103. false면 문서 생성 차단

organizations                              -- 지자체 / 문화유산 단체 / 모금기관
  id, name, type(GOV|HERITAGE|NPO), is_disaster_zone(bool)

donation_programs                          -- 사업 · 후원 대상 (시드 데이터)
  id, org_id, title, description, category

rewards                                    -- 답례품 (시드)
  id, org_id, name, point_value, category   -- 현금·귀금속·유가증권 카테고리 없음

document_drafts
  id, intent_id, doc_type, template_version
  payload(jsonb)                            -- 템플릿 슬롯 값
  gate_result(ESIGN_OK|ESIGN_INVALID|NON_BINDING)
  gate_reason(text), gate_statutes(text[])  -- 인용 조문
  body_md(text), pdf_path(text)
  status(DRAFT|REQUESTED|SIGNED|REJECTED|CANCELED|EXPIRED|ARCHIVED)

signature_requests
  id, draft_id, modusign_document_id(unique)
  embedded_url, embedded_url_expires_at     -- 2시간
  participants(jsonb), last_synced_at
  reject_reason(text)

evidences
  id, draft_id, pdf_path, sha256
  signed_at, signer_log(jsonb)

obligations                                -- FR-508. 생애주기 12점의 실체
  id, user_id, draft_id
  kind(RECURRING_DONATION|WILL_REVIEW|VOLUNTEER_TERM)
  due_at, status(PENDING|NOTIFIED|DONE|SKIPPED)
  payload(jsonb)                            -- 회차, 금액 등

assets                                     -- 트랙 C
  id, user_id, category, name, detail(jsonb)
  masked_identifier(text)                   -- 원문 저장 금지 (NFR-703)
  beneficiary_id?, story(text)              -- FR-404 "물건의 이야기"
  source_document_path?, extraction_confidence?

beneficiaries
  id, user_id, name, relation, contact

custodians                                 -- FR-405
  id, user_id, name, contact
  agreement_draft_id, granted_at            -- 서명 완료 전 null

webhook_events                             -- 아웃박스 (ADR-5)
  id, provider, external_event_id(unique)   -- 멱등성 키
  payload(jsonb), received_at
  processed_at, process_attempts, last_error

audit_logs                                 -- NFR-704
  id, actor_id, entity_type, entity_id
  action, prev_state, next_state, at, meta(jsonb)

gate_blocks                                -- FR-509 카운터
  id, doc_type, reason, statutes(text[]), at
```

### 저장 금지 목록 (NFR-703)
주민등록번호 · 계좌번호 · 카드번호 원문. 필요 시 `masked_identifier`에 `1234-56******` 형태로만.

## 2\. 문서 상태 머신

```markdown
                    ┌──────────┐
                    │  DRAFT             │◄──── 게이트 통과 시 생성
                    └────┬─────┘
                게이트 재확인 │ requestSignature()
                              ▼
                  ┌─────────────┐
        ┌────│  REQUESTED               │────────┐
        │        └──────┬──────┘                │
   거절 │             서명 완료 │                    만료/취소│
        ▼                       ▼                             ▼
  ┌──────────┐    ┌──────────┐    ┌───────────────────┐
  │ REJECTE                  │  SIGNED            │    │ EXPIRED / CANCELED                   │
  └────┬─────┘    └────┬─────┘    └─────────┬─────────┘
       │ 수정 후 재요청                │증빙 확보          │ 수정 후 재요청
       │  (새 문서)                    ▼                   │  (새 문서)
       │         ┌──────────┐                   │
       └───►│ ARCHIVED           │◄──────────┘
                 └──────────┘
                       │ Obligation 발동
                       ▼
                 갱신 → 새 DRAFT
```

### 전이 규칙
*   모든 전이는 `lib/modusign/state-machine.ts`의 **허용 전이 표**를 통과해야 한다. 표에 없는 전이는 예외를 던진다.
*   모든 전이는 `audit_logs`에 기록된다. 예외 없음.
*   `ESIGN_INVALID` 문서는 **`REQUESTED`****로 갈 수 없다.** 서버 레벨에서 차단(FR-104).
*   `NON_BINDING` 문서는 `DRAFT → ARCHIVED`로 직행한다 (서명 단계 없음).

### 상태 매핑 (외부 → 내부)

| 모두싸인 상태 | 내부 상태 |
| ---| --- |
| `ON_GOING` | `REQUESTED` |
| `COMPLETED` | `SIGNED` → 증빙 확보 후 `ARCHIVED` |
| 거절/중단 | `REJECTED` |
| 만료 | `EXPIRED` |

## 3\. 접근 제어 (Supabase RLS)

| 테이블 | 정책 |
| ---| --- |
| `intents`, `intent_facts`, `assets` | 본인만 |
| `document_drafts`, `evidences` | 본인 + 해당 org\_admin |
| `custodians` | 본인 + `granted_at IS NOT NULL`인 custodian |
| `audit_logs` | 읽기만, 쓰기는 서비스 롤 |
| `gate_blocks` | org\_admin 집계 조회 |

FR-605(다른 단체 약정 접근 거부)는 애플리케이션 코드가 아니라 **RLS로 강제**한다. 심사에서 "권한을 DB 레벨에서 막았다"고 말할 수 있어야 한다.
