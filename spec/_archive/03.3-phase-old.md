# 03.3 · Phase 6–7 — 유산 정리 & 관리 대시보드

## Phase 6 · 트랙 C — 유산 정리 (H+28 ~ H+36)

| ID | 작업 | 담당 | 시간 | 완료 판정 |
| ---| ---| ---| ---| --- |
| T601 `[D]` | Document Parse 연동 — 이미지·PDF 업로드 → 텍스트·표 추출 | A | 2h | ✓ 보험증권 샘플에서 텍스트 추출 성공 |
| T602 `[C]` | 문서유형별 IE 스키마 (보험증권·통장·등기부·증권잔고) + 마스킹 저장 | A | 2h | ✓ 주민번호·계좌번호 원문이 DB에 없음 |
| T603 | 판독 실패 시 빈 폼 전환 (오류 화면 금지) | C | 1h | ✓ 판독 불가 이미지 업로드 시 자연스럽게 수기 입력으로 전환 |
| T604 | 자산 인벤토리 화면 — 7개 카테고리, 신뢰도 낮은 항목 강조 | C | 2h | ✓ 카테고리별 집계 표시 |
| T605 | 채무 항목 존재 시 상속포기·한정승인 3개월 안내 | A | 0.5h | ✓ 채무 등록 시 안내 자동 노출 |
| T606 `[D]` | 디지털 유산 처리 지시 — 삭제/보존/이전 필수 선택 → `NON_BINDING` 문서 생성 | A+C | 1.5h | ✓ 게이트가 `NON_BINDING` 반환, 서명 단계 없이 보관 |
| T607 `[D]` | 수증자 매핑 + "물건의 이야기" 한 문단 (선택, 강제 아님) | C | 1.5h | ✓ 이유 작성 시 수증자 전달에 포함 |
| T608 | Custodian 지정 → 보관·집행 협조 약정 서명 요청 → 서명 완료 전 열람 차단 | B | 1.5h | ✓ 미서명 Custodian은 인벤토리 조회 불가 (RLS로 강제) |

> **T607이 이 트랙의 인간다움 지점이다.** 자산 목록은 어디에나 있지만, "왜 이 반지를 그 애에게 주는지"를 남기게 하는 서비스는 없다. 데모에서 이 한 화면이 15점짜리 항목을 설득한다.
