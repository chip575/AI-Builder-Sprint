# 03.0 · MVP 절단 계획 — 기능 나열과 명세 연결

> 옛 Phase 구조(03.1~03.4)를 대체하는 기준. **절단 단위는 기능 묶음이 아니라 "증명 가능한 명제"다.**  
> 각 MVP는 한 문장의 명제를 증명하고, 그 명제가 심사 배점과 1:1로 연결된다. 뒤에서부터 버린다 — M0·M1은 사수.

## 절단 원칙

1. **수직으로 자른다.** 화면만·백엔드만 완성된 층은 MVP가 아니다. 각 층은 진입→체결→보관까지 관통한다.
2. 모든 기능은 FR/NFR ID를 갖는다. **ID 없는 기능은 만들지 않는다** (01.4 추적성 규칙).
3. M0의 파이프라인 코드(구조화→게이트→문서→서명→보관)는 이후 모든 층이 **재사용**한다. 층이 올라가도 파이프라인은 하나다.

## M0 · "말이 서명이 된다" — 최소 관통 절단

**명제**: 한 문장의 발화가 법적으로 유효한 전자서명 문서가 되어 돌아온다.
**시나리오**: P3(고향 기부자) Express 1회 — "부산에 기부하고 싶어요" → 슬롯 대화 → 확인 → 게이트 → 기부약정서 → 모두싸인 실 서명 → 증빙.

| 기능 | 명세 | 연결 |
| ---| ---| --- |
| 단일 진입 + Express 판정 | FR-110, FR-115B | origin=EXPRESS 기록 → branch\_proposals |
| 기부 슬롯 대화 (1화면 1질문, 나중에 생각할래요) | FR-101 | 발화 → utterances |
| Solar 구조화 (신뢰도+원문위치) | FR-102, 02.5 §2 | utterances → intent\_facts |
| 확인·인라인 편집, 미확인 시 서버 거부 | FR-103 | facts.confirmed 게이트 조건 |
| 유효성 게이트 (3분기 전체 로직) | FR-104, 00.1 | facts → verdict, 유언 케이스는 픽스처로 검증 |
| 문서 생성 + 서명 요청 | FR-501, 02.3 | draft → modusign\_document\_id |
| 웹훅 즉시200 + 멱등 | FR-503 | webhook\_events UNIQUE |
| 증빙 보관 (PDF+해시) | FR-505 | evidences |
| mock 전 흐름 | NFR-707, 02.4 §4 | 키 없이 동일 경로 — 예선 에이전트 채점 경로 |
| 에이전트 보안 지침 + AI 로그 시작 | NFR-714 | [AGENTS.md](http://AGENTS.md) 커밋, [ai-log.md](http://ai-log.md) |

**완료 판정**: 실 계정 서명 왕복 1건 + mock으로 동일 흐름 재현 + 게이트 유닛테스트 통과.
**배점 연결**: 서명 플로우 15의 골격 · 문제정의 12(게이트) · 완성도(NFR-707).

## M1 · "체결이 끝이 아니다" — 생애주기·견고성

**명제**: 서명 이후에도 계약이 살아 있고, 연동은 유실에도 견딘다. (모두싸인 35점 완성)

| 기능 | 명세 | 연결 |
| ---| ---| --- |
| 거주지 차단(자기신고 고지)·상한 경고 | FR-201 | 게이트 2차 검사 |
| 세액공제 룰테이블 + 검산 유닛테스트 | FR-202, 00.1 | `[CALC:]` 토큰 → 계산 카드 |
| 답례품 30% 한도 | FR-203 | rewards 시드 |
| 정기후원 + 갱신 Obligation 자동 생성 | FR-204 → FR-508 | 체결 완료 훅 → obligations |
| 리컨실러 (웹훅 유실 복구) | FR-504 | cron → 상세조회 대조 |
| 거절 처리·리마인드 | FR-506·507 | REJECTED 사유, 48h 재발송 |
| 관리 대시보드 최소 (상태별·증빙 다운로드) | FR-601·602 | RLS 격리 |
| 종이 약정 옮기기 (DP+IE) | FR-401 응용, 02.4 §5 | 종이 기부약정 사진 → 갱신 체결. Upstage 가점 보호 장치 |
| 시간 압축 컨트롤 | 02.4 admin/advance-time | "주기 무관 관리" 성질의 시연 |

**완료 판정**: 웹훅 차단 상태에서 5분 내 상태 복구 + 갱신 알림이 시간 압축으로 재현.
**배점 연결**: 생애주기 12 · 견고성 8 · 실용성 20 · 가점(지역+Upstage).

## M2 · "마음이 축이 된다" — 회상·기록·분기

**명제**: 대화가 살아있는 유서가 되고, 법적 서류는 거기서 갈라져 나온다. (인간다움·창의성의 본체)

| 기능 | 명세 | 연결 |
| ---| ---| --- |
| 질문 은행 + 축 커버리지 엔진 | FR-301, FR-110 | question-bank.ts(코드) + Solar 진행 |
| 세션 재개 (주기 무관) | FR-110 | 재개 카드 — M3 Embeddings 전에는 최근 요약 폴백 |
| heart\_will 반영 제안 (AI 초안·사용자 확정·근거 발화) | FR-111 | heart\_will\_versions, source\_utterance |
| 보존·전달 시점·스냅샷 봉인 | FR-112 | reveal\_policy, snapshot\_hash → ledger |
| 가지 감지·제안 DETECTED + 무게 등급 | FR-115A | branch-weight.ts(코드) |
| 자필유언 필사 가이드 (서명 버튼 부재·4대 요건) | FR-302 | ESIGN\_INVALID 라우팅의 실물 |
| 마음의 편지 (AI/본인 문장 구분) | FR-303 | NON\_BINDING 보관 |
| 유산기부 약정 + 유류분 고지 + 숙려 화면 | FR-304, FR-115B | LEGACY\_GIFT — M0 파이프라인 재사용 |
| 접근성 기준 적용 | NFR-701·708 | P2 대표 형상 설계 근거 |

**완료 판정**: P2 시나리오 — 회상 2세션 → 유서 1버전 → 유산기부 가지 제안 → 다음 세션 재확인 → 체결.
**배점 연결**: 인간다움 15 · 창의성 20 · 문제정의(게이트 3분기가 화면으로).

## M3 · "시간에 서명한다" — 의사 이력·회상 검색

**명제**: 뜻이 바뀌는 과정 자체가 서명된 기록이 된다.

| 기능 | 명세 | 연결 |
| ---| ---| --- |
| 의사 확인서 + 실질성 등급 | FR-551·552 | MATERIAL만 재서명 — M0 서명 재사용 |
| 원장 노드 봉인 + 해시 체인 + 최신성 | FR-553·555 | intent\_ledger\_nodes append-only |
| 가족 인지 확인 서명 (다자) | FR-554 | M0 다자 서명 확장 |
| 유족 타임라인 + 검증 배지 | FR-556 | 시간 압축과 결합한 발표 피크 |
| Embeddings 회상 검색 | 02.5 §3 | 재개 카드 고도화 — 기간 무관 관리의 기술적 성립 |
| 이어쓰기 초대·재검토 | FR-113, FR-305 | obligations kind 확장 |

**완료 판정**: 수증자 변경 → 재서명 → 가족 인지 → 노드 ACTIVE/SUPERSEDED가 타임라인에 표시.
**배점 연결**: 생애주기 12 심화 · 서명 플로우 15(다자·다단계) · 창의성 20.

## M4 · 여력 — 자산정리 전체·부가

FR-401~405 ESTATE 전체(인벤토리·디지털 유산·Custodian 부분 열람 NFR-713) · Document Classification(선택) · P1 초대 흐름(결정 시) · FR-206 봉사(스키마+템플릿만 — 이미 확정) · 음성 입력.

## 층간 연결 한 장

```
M0 파이프라인 (구조화→게이트→문서→서명→보관) ─── 모든 층이 재사용
  ▲                    ▲                  ▲
M1: 체결 "이후"를 추가   M2: 진입 "이전"을 추가   M3: 변경 "과정"을 감쌈
   (Obligation·리컨실러)   (축→제안→가지 공급)      (문서를 원장 노드로)
M4: 가지 1종 추가 (ESTATE) — 파이프라인 무변경, 템플릿+스키마만
```
