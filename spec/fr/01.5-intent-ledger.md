# 01.5 · FR — 의사 이력 (Intent Ledger)

**이 페이지는** 체결 이후 **뜻이 바뀌는 과정**을 서명으로 남기는 구조(FR-550)를 다룬다.
핵심은 **FR-554 가족 인지 확인 서명** — 분쟁을 막는 건 문서가 아니라 "몰랐다"의 제거다.
연결된 배점은 생애주기 12 · 서명 플로우 15 · 인간다움 15 · 창의성 20.
주의: 서명 대상 문서명에 **"유언" 단어 금지** — 그 순간 민법 1066조 무효 논란으로 끌려간다.

흐름: `FR-551 의사 확인서` → `FR-552 실질성 등급` → `FR-553 노드 봉인` → `FR-554 가족 인지` → `FR-555 최신성` → `FR-556 유족 열람`
* * *

# FR-550 · 의사 이력 (Intent Ledger)

> FR-104는 "유언에 전자서명할 수 없다"는 제약을 인정했다. 이 절은 그 제약을 **우회하지 않고 뒤집는다.**

유언장의 유효성은 _한 시점_의 문제다. 아무도 풀지 않는 건 _시간에 따른 변화_다. 상속 분쟁에서 실제로 다투는 건 서식이 아니라 셋이다 — **① 당시 의사능력 ② 본인 진의(강요 여부) ③ 이게 마지막 뜻인가.**

서명된 타임스탬프 이력은 유언을 _유효하게_ 만들진 못해도 **믿을 만하게** 만든다.

> **유언장은 순간의 문서다. 사람의 뜻은 과정이다. 우리는 그 과정에 서명한다.**

문서의 단위가 `DocumentDraft` 하나에서 **노드들의 체인**으로 바뀐다.
* * *

## FR-551 · 의사 확인서 (서명 대상의 정의)

서명 대상은 유언이 아니라 **"오늘 시점에 다음 내용이 나의 뜻임을 확인한다"** 는 사실확인 문서.

*   문서명은 **`의사 확인서`** 로 고정. `유언변경서` 등 유언 연상 명칭 **금지** — 그 순간 무효 논란으로 끌려간다.
*   게이트 판정 `ESIGN_OK`. 본문에 유언 전문을 복제하지 않고 **해시 + 항목 요약만**.

**수락** · Given 생성 시 → `ESIGN_OK`이고 유언 전문 미포함 / 제목에 "유언" 미포함

## FR-552 · 변경의 실질성 등급 (서명 인플레이션 방지)

잦은 재서명 요구는 **그 자체가 마찰**이고(P4·NFR-708), 감정적으로 무거운 주제에서 특히 해롭다. 모든 변경에 서명을 요구하면 사용자는 변경 자체를 회피하게 된다 — 그러면 이력의 존재 이유가 사라진다.

| 등급 | 내용 | 처리 |
| ---| ---| --- |
| MATERIAL | 수증자·배분비율·기부처·기부액·Custodian | 재서명 |
| MINOR | 문구 다듬기, 오탈자, 연락처 | 버전만 증가 |
| ANNOTATION | 마음의 편지 추가 | 이력 append |

**수락** · 문구 수정 → 재서명 요구 없음 / 수증자 변경 → MATERIAL 판정 / 한 세션 2번째 서명 필요 시 **다음 세션으로 연기 제안**

## FR-553 · 원장 노드 봉인

**이게 없으면 이력은 역효과를 낸다.** 불만 있는 상속인이 "5번 바꿨다 = 판단력 없었다"로 공격할 수 있다. 각 노드가 **그 시점의 정황**을 함께 봉인하면 이력은 오히려 능력의 증거로 뒤집힌다.

노드에 봉인되는 것:
*   변경 전후 요약 + **변경 사유(본인 진술)**
*   서명 시각 · 서명자 · 서명 수단
*   **선택 정황 기록** — 입회인, 작성 환경 메모 등 (있는 경우에만)
*   직전 노드 해시 → **해시 체인**

**일반 사용자의 능력 정황은 별도 임상 기록이 아니라 시스템이 이미 가진 것들이 담당한다** — 대화 원문(조리 있는 발화 자체가 정황), 세션의 규칙성, 본인이 남긴 변경 사유. 임상적 컨디션 기록·의료진 입회는 **확산 단계(기관·말기 도입)의 강화 요건**이지 기본 요건이 아니다. 스키마의 `condition_note` · `witness` 필드는 그래서 선택(optional)이다.

**수락** · 임의 노드 1바이트 수정 → 이후 전체 불일치 표시 / 정황 기록 없이 생성된 노드도 유효

## FR-554 · 가족 인지 확인 서명 (다자·다단계) ★

**가장 강한 버전은 혼자 재서명하는 게 아니다.** 변경 시점마다 가족이 **"뜻이 바뀌었고 나는 알았다"** 에 함께 서명한다. 분쟁을 막는 건 문서가 아니라 **"몰랐다"의 제거**다.

*   가족 서명은 **동의가 아니라 인지**. 동의로 읽히면 유류분 포기 오해가 생긴다.
*   본인이 통지 대상을 지정하고, **통지하지 않을 자유도 보장**한다 (P4).

**수락** · MATERIAL 확정 시 본인→가족 순 다자 요청 / 가족은 변경 내용과 **본인의 변경 사유**를 함께 열람 / 가족 거부해도 본인 확인서 효력 유지, 거부 사실만 기록

## FR-555 · 최신성 판정

전후 유언이 저촉되면 뒤엣것이 우선한다. **"어느 게 최신인가"가 그 자체로 소송거리다.**

**수락** · 유효 노드가 **단 하나로 특정**되고 나머지 `SUPERSEDED` / 철회 시 `REVOKED`, 원본 물리 삭제 없음

## FR-556 · 유족 열람 뷰

Custodian·유족이 원장을 **시간순 타임라인**으로 열람. 각 시점의 사유·서명자·(있다면) 정황 기록 + **해시 검증 결과**. 열람은 `audit_logs`에 기록.
* * *

## 데이터 모델 (02.4에 통합됨)

```
intent_ledger_nodes
  id, user_id, subject_id
  seq, materiality(MATERIAL|MINOR|ANNOTATION)
  change_summary(jsonb), change_reason(text)
  condition_note(text)?   -- 선택 · 정황 메모 (확산 단계 강화용)
  witness(jsonb)?         -- 선택 · 입회인
  draft_id?               -- MATERIAL일 때 의사 확인서
  prev_hash, node_hash    -- 해시 체인
  status(ACTIVE|SUPERSEDED|REVOKED), created_at
```

**불변식** — append-only. UPDATE·DELETE 금지. 정정도 새 노드로.

## 상태 머신

```
노드 생성 → materiality 판정
  ├ MINOR/ANNOTATION → 즉시 ACTIVE (서명 없음)
  └ MATERIAL → 의사확인서 DRAFT → REQUESTED
                ├ 본인 서명 → (대상 있으면) 가족 인지 서명
                └ 전원 완료 → 노드 ACTIVE + 직전 노드 SUPERSEDED
```

## 심사 배점 대응

| 배점 | 기여 |
| ---| --- |
| 생애주기 12 | 체결이 끝이 아니라 변경·재확인·승계까지가 한 계약임을 구조로 증명 |
| 서명 플로우 15 | 다자(본인+가족)·다단계(변경마다) 실 서명 왕복 |
| 인간다움 15 | 변경 사유를 본인 말로 남기고 가족이 그것을 읽고 서명 |
| 창의성 20 | 전자서명이 불가능한 영역에 서명하는 유일한 방법 |

## 데모 · 예상 반문

관리자 시간 압축(+6/+12개월) → 재검토 → 변경 → 실질성 판정 → 재서명 → 가족 인지 서명 → 노드 추가. **30초 한 사이클.** 실제 스케줄러·게이트·상태머신을 그대로 통과시킨다.

> **"그거 그냥 버전 관리 아닌가요?"**  
> 버전 관리는 내가 나에게 하는 기록이고, 서명은 제3자에게 하는 증명이다. 상속 분쟁은 법원과 다른 상속인 앞에서 벌어진다. Git 로그는 증거가 안 되지만 전자서명된 문서는 증거가 된다.
