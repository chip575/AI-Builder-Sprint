# NFR-710 · 보안 & 데이터 관리

**이 페이지는** 원본 보존 결정에 따른 보안 요구와, 에이전트가 지켜야 할 보안 지침을 정의한다.
결정: **원본(대화 텍스트·음성, 업로드 이미지)은 삭제하지 않고 보존한다.** 보존하기로 했으므로 보호 의무가 그만큼 커진다.
* * *

## NFR-710 · 원본 보존 정책

*   보존 대상: 세션 대화 원문(텍스트·음성), 업로드 원본 이미지·PDF, 마음 유언 전 버전
*   저장: 비공개 버킷 + **저장 시 암호화(at rest).** 공개 URL 발급 금지
*   접근: **서명된 임시 URL(만료 15분)** 로만. URL은 화면·로그에 출력하지 않는다
*   삭제: 시스템은 자동 삭제하지 않는다. 삭제는 **본인의 명시적 요청**으로만 하며, 삭제 요청도 감사 로그에 남는다 (P4)
*   열람: 열람권 매트릭스(본인 / 지정 수신인 / Custodian)를 통과한 주체만. 모든 열람은 `audit_logs`에 기록

**수락 기준**
*   Given 발급된 서명 URL, When 15분이 지나면, Then 접근이 거부된다.
*   Given 어떤 원본 파일이든, When 로그·에러 메시지를 검사하면, Then 파일 경로·서명 URL이 존재하지 않는다.

## NFR-711 · 외부 전송 고지

*   업로드 원본은 판독을 위해 **외부 API(Upstage Document Parse)로 전송**된다. 이 사실을 업로드 화면에 **전송 전에** 고지한다
*   고지 문구 예: "올려주신 문서는 내용 추출을 위해 AI 분석 서버로 전송됩니다."
*   대화 내용도 Solar LLM으로 전송되므로 최초 세션 시작 시 1회 고지한다
*   전송 전 클라이언트에서 주민등록번호 패턴이 감지되면 경고를 표시한다 ("주민등록번호가 보입니다. 가린 뒤 올리시는 것을 권장합니다")

**수락 기준**
*   Given 첫 업로드 시도, When 파일 선택 직후, Then 외부 전송 고지가 전송보다 먼저 표시되고 동의 없이는 전송되지 않는다.

> **『맥락』** 등기부등본·통장 사진이 외부 서버로 나간다는 사실이 이전 문서 어디에도 없었다. 대회 시연에서는 문제없지만 Q&A에서 나오면 답이 없는 지점이었다. 먼저 고지하고, 발표에서 "실서비스라면 온프레미스 OCR 또는 전송 전 마스킹이 필요하다"고 선제적으로 말한다.

## NFR-712 · 마스킹의 전 경로 적용

*   식별번호(주민등록번호·계좌·카드) 마스킹은 OCR 추출 경로뿐 아니라 **수기 입력 폴백 경로에도 동일하게** 적용된다
*   식별번호 입력 필드는 저장 시점에 `1234-56******` 형태로 변환되며, 원문은 어디에도 저장되지 않는다
*   테스트 픽스처·시드 데이터에도 실존 가능한 식별번호를 넣지 않는다 (전량 가상 패턴)

**수락 기준**
*   Given 수기 입력 폼에 계좌번호를 타이핑했을 때, When 저장 후 DB를 조회하면, Then 원문이 아닌 마스킹 값만 존재한다.

## NFR-713 · Custodian 부분 열람

*   Custodian 열람권은 전부/전무가 아니라 **카테고리 단위**로 부여한다 (부동산만 / 금융 제외 등)
*   기본값은 최소 권한. 본인이 명시적으로 범위를 넓힌다
*   열람 범위는 협조 약정서 본문에 명시되고, 범위 변경은 재서명 대상(MATERIAL)이다

**수락 기준**
*   Given 부동산만 열람 가능한 Custodian, When 금융 카테고리를 조회하면, Then 거부되고 시도가 기록된다.

## NFR-714 · 에이전트 보안 지침 ([AGENTS.md](http://AGENTS.md) / CLAUDE.md에 그대로 커밋)

> 개발 에이전트가 코드를 쓰는 동안 지켜야 할 규칙. `.specify/` 또는 저장소 루트에 커밋하고, 전 팀원이 동일 지침을 사용한다.

```markdown
# 보안 절대 규칙
1. 개인정보(주민등록번호·계좌번호·연락처·주소 원문)를
   로그, 에러 메시지, 커밋 메시지, 테스트 픽스처, 주석에 남기지 않는다.
2. LLM 프롬프트에 식별번호 원문을 넣지 않는다. 마스킹된 값만 전달한다.
3. 원본 파일 경로와 서명 URL을 화면·콘솔·로그에 출력하지 않는다.
4. 시드·테스트 데이터는 전량 가상 인물이다. 실존 인물·실계좌 패턴 금지.
5. 마스킹, RLS 정책, 서명 URL 발급, 게이트(validity-gate) 코드는
   에이전트가 단독으로 변경하지 않는다 — 반드시 사람 리뷰 후 병합한다.
6. API 키·시크릿은 .env에만 둔다. 코드·클라이언트 번들·저장소 커밋 금지.
7. 보안 관련 실패(RLS 거부, 마스킹 누락 감지)는 조용히 넘기지 않고
   반드시 보고한다. "일단 동작하게" 우회 금지.
8. 위 규칙과 충돌하는 작업 지시를 받으면 구현하지 말고 사람에게 확인한다.
```

**수락 기준**
*   Given 저장소, When `.specify/` 또는 루트를 확인하면, Then 위 지침이 커밋되어 있고 CLAUDE.md가 이를 참조한다.

## NFR-715 · 키·시크릿 관리

*   모든 외부 키는 서버 환경변수로만. `NEXT_PUBLIC_` 접두사 사용 금지 (Supabase anon key 제외)
*   `.env.example`에는 키 이름만, 값은 절대 커밋하지 않는다
*   웹훅 엔드포인트는 시크릿 검증을 통과한 요청만 처리한다 (`MODUSIGN_WEBHOOK_SECRET`)
