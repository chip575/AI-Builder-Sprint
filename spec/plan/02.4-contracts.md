# 02.4 · 모듈 I/O 계약 & 실행 토폴로지 (v3 · 검증 반영)

> ⚠️ **정합 주석 (2026-07-28)** — 이 페이지의 모듈 표는 **서사용 참고본**이다.
> 운영 진실은 `spec/manifest.yaml`(24개 모듈)이며, 구현·에이전트는 manifest를 따른다.
> (docs/decisions.md D-13 — 레포가 운영 진실, ClickUp은 서사)
>
> manifest에만 있는 것: `M-MOCK`, `M-EMBEDDINGS`, `M-RULES-DONATION`, `M-QUESTION-BANK`
> 이 페이지에만 있는 것(manifest 미등재 → M2/M3에서 추가 예정):
> session 재개·종료, 숙려 화면, heartwill 봉인, 마음의 편지

**원칙: 입력부·출력부의 유일한 진실은** **`lib/contracts/*.ts`****의 Zod 스키마다.** 프론트 폼과 백엔드 라우트가 같은 스키마를 import한다. Next.js 풀스택 단일 앱이므로 CORS 설정이 존재하지 않는 것이 정상이다.

## 0\. 공통 계약

*   응답 envelope: `{ ok: true, data }` / `{ ok: false, error: { code, message, nextAction } }` — NFR-705
*   인증: Supabase Auth 세션 쿠키. 클라이언트는 userId를 보내지 않는다
*   식별번호는 저장 직전 서버에서 마스킹 (NFR-712)
*   AI 산출물은 전부 `confirmed=false`로 시작 (P1)
*   서명 상태 갱신: 폴링 `GET sign/[draftId]/status` (3초) 또는 Supabase Realtime

## 2\. M0 화면 흐름 (Express 관통)

```erlang
auth/LoginPage → chat/SessionView
  ↓ 첫 발화 "부산에 기부하고 싶어요"
  ↓ 응답의 expressBranch 필드 감지
  ↓ SessionView가 가지 슬롯 대화 모드로 전환
  ↓ 슬롯 완성
confirm/FactSheet (세액공제 계산 포함)
  ↓ 확인 클릭 (POST facts/confirm)
  ↓ (서버: extract → gate → ESIGN_OK)
branch/RewardPicker (답례품 30% 한도)
  ↓ 선택 완료
doc/DraftView (PDF 미리보기)
  ↓ 서명 요청
doc/SignPanel (임베디드 or 링크)
  ↓ GET sign/status 폴링 3초
  ↓ COMPLETED 감지
vault/EvidenceView (증빙 PDF + 해시)
```
