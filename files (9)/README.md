# 모두싸인 서식 8종 — 계약서 체재

## 수정 이력

| 판 | 무엇을 | 왜 |
|---|---|---|
| v1 | Typst로 8종 생성. 클린 / 가이드 2벌 | 최초 |
| v2 | 계약서 체재로 전면 개편 | 업로드해 주신 4종이 계약서처럼 보이지 않는다는 지적 |
| v2.1 | 필드 칸 다행 지원 + `schema/` 추가 | 긴 값이 칸에서 잘리면 계약 하자 |
| **v3** | **전 서식 1페이지 확정** | 문서가 페이지를 벗어남 |

### v3에서 바뀐 것 (이번)

**1페이지 강제.** 8종 중 7종이 2페이지였고, 넘친 양은 ⑧ 10%부터 ② 48%까지였습니다. 세 단계로 줄였습니다.

| 방법 | 내용 |
|---|---|
| 조판 압축 | 본문 9.5pt → 8.9pt, 자간 0.76em → 0.68em, 여백 20/18/15mm → 17/14/11mm, 표제 18pt → 15.5pt, 필드 칸 줄높이 5.0mm → 4.2mm |
| 조문 통합 | ①②④의 `통지` 조문을 최종 일반조항 ①항으로 편입. ②는 `출금 실패`를 제5조에, `조건의 변경`을 제6조에 편입 |
| 서명란 재배치 | 당사자 2인을 위아래 → **좌우 나란히**. 서명 박스 14mm → 10mm |

조문 수: ① 10→9, ② 12→9, ④ 11→10. **삭제한 조문은 없습니다.** 전부 다른 조의 항으로 옮겼고, 번호 연속성과 상호참조도 다시 맞췄습니다. 필수 문구·금칙어 검사는 그대로 통과합니다.

**칸 용량은 오히려 늘었습니다.** 여백과 라벨 칸이 줄어 값 칸이 넓어졌습니다.

| | v2.1 | v3 |
|---|---|---|
| 값 칸 폭 | 126mm | 135.8mm |
| 한 글자 | 9.43pt | 8.60pt |
| 한 줄 용량 | 37.9자 | **44.8자** |
| 스키마 상한 | 36 | 36 (그대로) |

상한 36을 유지했으므로 **`schema/`는 수정할 필요가 없습니다.** 여유가 1.9자에서 8.8자로 늘었을 뿐입니다.

**HTML도 같이 맞췄습니다.** 조문 수가 PDF와 정확히 일치하고(9·9·7·10·10·7·7·9), 인쇄 시에도 1페이지로 떨어지도록 print CSS를 따로 넣었습니다.

## 무엇이 바뀌었나

**받아들인 것 (업로드본에서)**

- 번호 붙은 절 구조 — `1. 당사자 / 2. 약정 내용 / 3. 약정 사항`. 제 v1은 표가 하나로 뭉쳐 있어 읽기 나빴습니다.
- 평이한 항목명 — `수집하는 항목 / 이용하는 목적 / 보유하는 기간`. 한자어 명사구보다 낫습니다.
- ②의 "본 약정은 출금에 대한 동의가 아니다" — 제3조제2항으로 승격시키고 굵게 뺐습니다.

**계약서 체재로 추가한 것**

| 요소 | 내용 |
|---|---|
| 두문(前文) | "…기부자와 기관은 다음과 같이 약정을 체결한다" |
| 당사자 표시 | 기부자 / 기관을 절 1에서 표로 병기 |
| 조·항 계층 | 제N조(표제) 아래 ① ② ③ |
| 일반조항 | 통지 · 신의성실 · 분쟁의 해결(협의 → 관할) |
| 말미문언 | "본 약정의 성립을 증명하기 위하여 … 각자 보관한다" |
| 날인란 | 기관 대표자 + (직인) |

**고친 것**

③의 전자기부금영수증 문구를 사실관계에 맞게 바꿨습니다. 업로드본은 "주민등록번호를 대신하여 휴대전화번호로 발급받을 수 있습니다"로 단정했는데, 국세청 설명상 이 제도는 **기부자가 먼저 홈택스에 휴대전화번호를 등록하고 개인정보 제공에 동의해야** 쓸 수 있습니다. 게다가 주민등록번호는 기부금영수증의 필수 기재사항이라 단체가 출력할 때는 표시됩니다. "주민번호 없이 발급된다"로 읽히면 사실과 달라서, 제4조를 3개 항으로 나눠 ① 법령상 의무 처리 ② 전자기부금영수증 이용 조건 ③ 그래도 주민번호가 완전히 배제되지는 않는다는 한계까지 적었습니다.

## 계약서로 만들지 않은 3종

③⑥⑦은 **일부러 쌍무 계약 구조를 넣지 않았습니다.**

- **③ 개인정보 동의서** — 동의는 정보주체의 단독 의사표시입니다. 갑·을 계약으로 만들면 법적 성격이 달라집니다.
- **⑥ 의사 확인서** — 본인 단독 확인입니다. 상대방 당사자를 두면 그 성격이 흐려집니다.
- **⑦ 가족 인지 확인서** — 여기가 가장 중요합니다. **계약서처럼 보일수록 가족이 무언가에 합의한 것으로 읽혀 위험이 커집니다.** 가이드가 "동의" 표현을 금지한 이유와 정확히 같은 이유입니다. 제3조제1항에 "권리·의무를 발생시키는 계약이 아니다"를 명시적으로 넣었습니다.

이 셋도 조·항 계층, 절 번호, 말미문언, 서명란은 갖췄으므로 문서로서의 격식은 동일합니다. 빠진 건 두문의 당사자 대치 구조와 날인란뿐입니다.

## 서명자 수는 그대로입니다

계약서 체재가 되면서 기관 서명란이 생겼지만, **기관 측은 서식에 미리 인쇄하는 부분이고 모두싸인 참여자가 아닙니다.** 참여자로 잡으면 서명자가 2명이 되어 등록 사양과 어긋납니다. 가이드 PDF에서 해당 칸에 `[미리 인쇄 · 참여자 아님]`으로 표시해 뒀습니다.

서명자 수: ①~⑥⑧ 각 1명, ⑦만 2명(본인 → 가족 순차).

## 참조한 근거

- ① 「고향사랑 기부금에 관한 법률」 시행령 — 지자체는 별지 서식 기탁서를 받고 지정 금융기관 또는 정보시스템으로 접수. 제4조제2항을 이 절차에 맞췄습니다.
- ② **금융결제원 「CMS 출금이체 신청(동의)서」 표준문안** — 이용기관이 형태는 바꿔 쓸 수 있으나 고객 기재내용과 동의항목 등 주요 내용은 변경 불가. 전자금융거래법 제15조는 추심이체 전 출금 동의를 요구합니다. **그래서 ②를 출금 동의서로 만들지 않고 제3조제2항에서 명시적으로 분리했습니다.**
- ③ 「개인정보 보호법」 제15조제1항제1호·제2호, 제17조, 제22조, 제24조의2, 제29조 / 국세청 전자기부금영수증 안내
- ④ 「민법」 제1060조·제1065조 이하(유언의 요식성). 유류분은 조문 번호와 비율을 넣지 않았습니다 — 2024년 헌재 결정 후 민법이 개정되어 2026년 3월 시행되었고, 배우자·직계비속의 유류분은 유지되고 있습니다.
- ⑤ 「국가유산기본법」 (2024년 문화재 → 국가유산 체계 전환)
- 전 서식 「전자문서 및 전자거래 기본법」

## 입력 스키마 (`schema/`)

데이터 라벨에 들어가는 값은 **서명되는 계약서 본문의 일부**가 됩니다. 그래서 입력 검증은 UX가 아니라 법적 통제로 다뤘습니다.

| 파일 | 용도 |
|---|---|
| `fields.schema.json` | JSON Schema 2020-12. 8종 전체의 타입·필수·길이 |
| `guards.mjs` | 실행 가능한 검증기. 금칙 패턴, 서식 간 정합성, 칸 넘침 |
| `types.d.ts` | TypeScript 타입 |

```js
import { validate } from './schema/guards.mjs';
const r = validate('RECURRING_CONSENT', payload);
if (!r.ok) throw new FieldError(r.errors);
await modusign.createDocument(TEMPLATE_ID.RECURRING_CONSENT, r.fields);
```

`r.fields`는 전부 문자열입니다. `amount_krw: 100000` → `"100,000원"`, `first_debit_date: "2026-09-05"` → `"2026년 9월 5일"`, `is_anonymous: true` → `"익명 희망"`으로 바뀝니다. boolean이나 숫자를 그대로 보내면 서면에 그대로 인쇄됩니다.

### 새로 채워야 하는 필드

| 키 | 서식 | 성격 |
|---|---|---|
| `org_contact` | ② | **법적으로 필수.** 제2조 해지 방법 고지의 연락처 자리이며, 비면 해지 방법 요건이 성립하지 않습니다 |
| `org_rep` | ①②④⑤ | 선택. 기관 대표자. 미지정 시 빈칸 |
| `org_name` | ③⑤ | 선택. ③은 개인정보처리자, ⑤는 기관 명칭 |

기관 정보가 서식마다 고정이라면 키를 잡지 말고 서식에 인쇄하는 편이 낫습니다.

### 칸 용량과 길이 제한

값 칸 한 줄은 실측 37.9자(9.43pt/자 × 126mm)입니다. 여유를 두어 **한 줄당 표시 폭 36**으로 잡았고, 긴 항목에는 2~3줄 칸을 줬습니다. 한글·전각 1, ASCII·반각 0.5로 셉니다.

| 줄수 | 상한 | 해당 필드 |
|---|---|---|
| 1줄 | 36 | 이름, 금액, 날짜, 기관명, 관계 |
| 2줄 | 72 | `program_title` `retention_period` `effective_condition` `heritage_name` `purpose`(⑤) `content_hash` `view_scope` |
| 3줄 | 108 | `collect_items` `purpose`(③) `asset_summary` `items_summary` `change_summary` `change_reason` `duties` |

넘치면 렌더링에서 잘립니다. **계약서 내용이 빠진 것이 되어 그 자체로 하자**이므로 `OVERFLOW`는 경고가 아니라 거부입니다.

| 코드 | 규칙 |

## 남은 할 일

- **②의 `org_contact`** — 제2조 고지 박스의 해지 연락처 자리입니다. 기관 실제 번호로 채우거나 서식에 인쇄하세요. 비워두면 해지 방법 요건이 약해집니다.
- **⑤의 `is_anonymous`** — "익명 희망" / "실명 공개" 같은 문자열로. `true`/`false`는 그대로 인쇄됩니다.
- **⑦ 상담 용어** — 업계에서는 흔히 "가족 동의"라고 부르지만, 문서만 "인지"로 쓰고 상담에서 "동의"라고 하면 방어선이 무너집니다. 스크립트도 맞춰주세요.
- **CMS 출금 동의서** — 9번째 서식으로 만들 거라면 금융결제원 표준문안을 그대로 가져와야 합니다. 우리가 문안을 쓰면 안 됩니다.
