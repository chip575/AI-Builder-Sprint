  때려 ① 인메모리 전제 테스트가 깨지고 ② **실 DB에 테스트 데이터가 영구히 쌓인다**
  (utterances는 물리 삭제 불가)
- **④' `pnpm e2e` DATA_MODE=supabase로 12단계 PASS.**
  중간에 evidence 500 → 원인: PostgREST가 `+00:00` 오프셋을 주는데 계약은 `Z`만 허용.
  **계약이 아니라 어댑터(번역 계층)에서 ISO(Z) 정규화**. 이 부류를 스위트가 먼저
  잡도록 시각 형식 단언 추가
- **⑤' 웹훅 멱등 실 DB 리허설: 동일 eventId 5회 POST → 전부 200, DB 1행, 처리 완료.**
  UNIQUE 제약이 진짜가 된 순간 (견고성 8점의 실체)
- ⚠ **DB에 개발 데이터 누적 중** (intents 114 · utterances 76 · evidences 17 등).
  utterances·evidences·audit_logs는 트리거로 삭제 불가 — 되돌릴 수 없다.
  데모/제출 전 **깨끗한 프로젝트(또는 Supabase 브랜치)로 전환 검토** 필요
- ⚠ **UPSTAGE_MODE·MODUSIGN_MODE는 여전히 mock** (real 전환 시도가 저장 안 된 듯).
  real 전환의 실제 효과: Upstage=과금 시작, 모두싸인=real 어댑터 미구현이라 명시적 실패

### §G 갱신 5 — 모드 관측 + DB 수명 정책
- **기동 로그 1줄**: `[mode] DATA=supabase UPSTAGE=mock MODUSIGN=mock`
  (instrumentation.ts → lib/observability/mode.ts). real이면 경고도 함께.
  ".env에 썼는데 왜 mock이지?"를 추측이 아니라 로그로 판정한다.
  ※ Next는 `.env.local`이 `.env`를 덮는다 — 편집한 파일과 로드된 파일이 다를 수 있다
- **DB 수명 정책**: DB 인스턴스는 소모품, 마이그레이션 파일이 진실 (D-13의 DB 버전).
  개발 데이터 누적은 트리거가 의도대로 동작한 결과이므로 지우려 하지 않는다.
  **데모 D-1: 클린 Supabase 프로젝트 새로 생성 → `db push` + 시드 (5분)**.
  두 번째 프로젝트를 지금 만들어 이중 관리하지 않는다 (브랜칭은 유료 티어)
- GitHub 원격: 계정 미보유로 보류 (온보딩·훅 Node 경화의 전제라 확보 시 재개)

### §G 갱신 7 — M-AUTH 완료 = M0 코드 완료 (2026-07-30)
- Supabase Auth 위임. 쿠키(httpOnly·SameSite)가 진실 — 클라이언트는 userId를 보내지 않는다
- **NFR-707 DoD 통과**: `.env`를 치우고 실행 → `[mode] DATA=memory`,
  화면 200(벽 없음), 로그인 시도는 503 AUTH_DISABLED + "그대로 진행" 안내,
  **키 없는 e2e 14단계 PASS**. 인증 활성 시엔 /chat → 307 /auth?next=
- **미들웨어 제외 확인**: webhooks 200 · dev 도구 200 (matcher는 화면만.
  API는 각 라우트가 getCurrentUserId로 소유 필터를 건다 — D-18)
- 소유 필터 실연결: 세션 생성·증빙 조회가 DEV_USER_ID 상수 → 실제 사용자로 교체

#### ⚠ _pending 마이그레이션 승격은 **지금 하지 않는다**
`user_id NOT NULL + auth.users FK`인데, 현재 DB에는 DEV_USER_ID 행이 114건 있고
그 uuid는 auth.users에 없다 → 승격 시 FK 위반으로 실패한다.
**데모 D-1 클린 프로젝트 생성 시점에 함께 적용**한다 (DB는 소모품·파일이 진실).
그때 순서: 새 프로젝트 → `supabase migration new user_id_not_null`로 승격 →
`db push` → 시드. 키 없는 경로는 그때도 DEV_USER_ID를 쓰므로,
승격 후에는 **키 없는 모드에서 Supabase를 쓰지 않는다**는 전제가 유지돼야 한다
(현재 구조가 이미 그렇다 — 키 없으면 인메모리)

### §G 갱신 8 — realSigner(모두싸인) 작성 (2026-07-30, 키 없이)
공식 문서 확인 (전부 2026-07-30, developers.modusign.co.kr 한정):
- POST /documents/request-with-template · GET /documents/{id} ·
  POST /documents/{id}/cancel(message 2~200자 필수) · POST /documents/{id}/remind-signing
- 인증 `Authorization: Basic` · 본문 UTF-8 필수 · metadatas [{key,value}] 최대 10개

🔴 **발견: 우리 mock의 웹훅 이벤트명이 실제와 달랐다.**
  `document_completed`는 존재하지 않는다 → 실제는 **`document_all_signed`**.
  `document_requested` → `document_started`, `document_canceled` →
  `document_request_canceled`/`document_signing_canceled`.
  (`document_signed`는 "마지막 서명자 제외"라 완료가 아니다 — 상태를 옮기지 않는다)

  real 전환에서 그대로 터진다.

🔴 **상태 enum도 다르다.** 모두싸인은 DRAFT/SCHEDULED/ON_GOING/MODIFYING/
  APPROVAL_PENDING/ON_PROCESSING/PROCESSING_FAILED/ABORTED/COMPLETED.
  `mapModusignStatus()`로 번역 — ABORTED는 abort.type이 REJECTION이면 거절,
  아니면 취소. PROCESSING_FAILED는 상태를 옮기지 않고 리컨실러가 재확인.

구현: `lib/signer/real/modusign.ts` — fetch 주입(네트워크 없이 테스트),
  429·5xx 지수 백오프 재시도 + 타임아웃, 4xx는 즉시 실패, 템플릿 미등록은

  명시적 실패** (도메인 제한 실측이 필요 — 02.3 검증 게이트).
  테스트 15종(요청 조립·상태 매핑·재시도·404) 전부 픽스처 기반.

  임베디드 도메인 제한 · 템플릿 필드 주입 · **웹훅 실 페이로드**(공식 문서에

### §G 갱신 9 — realExtractor(Solar) 작성 (2026-07-30, 키 없이)
근거: https://console.upstage.ai/api/docs/for-agents/raw (2026-07-30 확인)
- POST https://api.upstage.ai/v1/chat/completions · `Authorization: Bearer`
- model `solar-pro3` · `reasoning_effort: minimal`(02.5 §4) ·
  `response_format: {type:"json_schema", json_schema:{name, schema}}` ·
  결과는 `choices[0].message.content`(JSON 문자열)

설계 (D-08 전제 유지):
- **모델에게 confidence를 묻지 않는다.** 스키마는 key·value·sourceText만 요구.
  신뢰도는 우리 정규화 계층이 산출 — 근거 발화에 숫자 명시=HIGH, 어림 표현=MEDIUM,
  **근거를 대화에서 못 찾거나 값과 어긋나면 LOW**(환각 방어)
- 2중 방어: JSON 파싱 실패 → 명시적 실패 / 파싱 성공 후 `IntentFactList.parse()` 재검증
- 요청하지 않은 슬롯은 버린다. 키 없이 real이면 mock 폴백 없이 명시적 실패
- 프롬프트에 법률 수치 0 — 테스트가 **단어가 아니라 수치**로 검사(gate:check 2번 기준).
  "세금·공제·한도는 다른 곳에서 처리한다"는 계산 금지 지시라 오히려 있어야 한다
- 픽스처 발화는 **데모 대본 그대로** — 키 도착 후 같은 입력으로 mock vs real 대조 →
  그것이 ADR-7 측정(D-08)의 예행
