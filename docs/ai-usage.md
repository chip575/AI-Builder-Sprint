# AI를 어떻게 썼는가

## 한 줄

> **AI로 코드를 짠 게 아니라, AI가 코드를 짜도 무너지지 않는 구조를 짰다.**

코딩 에이전트로 개발할 때 진짜 문제는 속도가 아니라 **검증 불가능성**이다.
생성물이 늘어날수록 사람이 따라가지 못하고, 명세와 코드가 어긋나도 아무것도 깨지지 않는다.
그 지점을 여러 층으로 막았다.

---

## 1. 명세를 두 번 내렸다

작업 순서가 `헌법 → 명세(FR) → 계약(모듈 I/O) → 절단(MVP) → 구현`이다.
`spec/`이 그 산출물이고, 커밋마다 FR ID가 붙는다.

**검증 가능한 형태로 내린 것이 핵심이다.** 명세가 문서로만 있으면 지켜지는지 알 수 없다.
그래서 같은 명세를 두 번 썼다.

| 층위 | 어디에 | 위반하면 |
|---|---|---|
| 서사·근거 | `spec/**` | 사람이 읽고 판단 |
| **입출력 계약** | `src/lib/contracts/*.ts` (Zod 25파일) | **`tsc --noEmit` 실패** |
| 작업·소유 경로 | `spec/manifest.yaml` | 훅이 차단 |

계약이 코드가 되는 순간 스펙 위반이 타입 에러가 된다. 런타임에서도 막힌다 —
라우트가 응답 직전 `parse()`를 통과시킨다.

**실제로 잡혔다**: mock signer가 상대 경로 URL을 반환했는데 `SignRes`의
`z.string().url()`이 런타임에서 거부했다. 계약이 mock 코드까지 검사한 사례다.

## 2. 판단은 코드에, 문장만 AI에

법률 수치·판정·법정 문안은 **전부 코드**다. LLM은 그 결과를 설명만 한다.

- 세액공제 계산 → `src/lib/rules/hometown-donation.ts` (검산 3케이스가 유닛테스트)
- 게이트 판정 → `src/lib/rules/validity-gate.ts` (순수 함수. `Record<DocType, …>`라
  문서 유형이 늘면 판정 누락이 타입 에러가 된다)
- Express 판정 → `src/lib/rules/express-detect.ts` (패턴은 코드, 애매한 것만 LLM)
- **자필 유언 문안 → `src/lib/rules/handwriting-guide.ts`**

마지막 항목은 원칙의 확장이다. 법정 요건 문장은 **한 글자 차이로 무효**가 될 수 있어서,
"수치는 코드만"을 "법정 문안도 코드만"으로 넓혔다. LLM은 유언 초안 본문을 쓰지 않는다.

프롬프트에 숫자가 섞이는 것도 막는다 — `gate:check`가 `src/lib/ai/**`를 스캔한다.
추출 프롬프트 테스트는 **단어가 아니라 수치 패턴**을 검사한다
(`세금·공제·한도는 다른 곳에서 처리한다` 같은 *계산 금지 지시*는 오히려 있어야 하므로).

## 3. 신뢰도는 모델이 아니라 우리가 정한다

Solar가 필드별 confidence를 반환하는지 확인되지 않았다. 그래서 **묻지 않는다.**
스키마는 `key·value·sourceText`만 요구하고, 신뢰도는 정규화 계층이 산출한다.

| 근거 | 신뢰도 |
|---|---|
| 원문에 숫자가 명시 ("100만원") | HIGH |
| 수량·어림 표현을 해석 ("한 십만원쯤") | MEDIUM — 확인 화면에서 강조 |
| **근거를 대화에서 못 찾거나 값과 어긋남** | LOW — 항상 되묻는다 (환각 방어) |

실호출로 확인했다: "한 십만원쯤" → `100000 (0.6)`, "부산" → `부산 (0.95)`.
모델이 나중에 confidence를 주기 시작해도 **매핑만 바꾸면 되고 인터페이스는 그대로**다.

그리고 진짜 안전장치는 임계값이 아니다 — **금액·수증자·기관명은 신뢰도와 무관하게
항상 사용자 확정을 거친다.** 임계 0.7은 "무엇을 강조하고 되물을까"를 정할 뿐이다.

## 4. 에이전트 하네스 — 모델을 난이도에 맞춘다

`.claude/agents/`에 세 종류를 정의하고 각 파일에 **모델 선택 이유**를 주석으로 남겼다.

| 에이전트 | 모델 | 이유 |
|---|---|---|
| `impl-worker` | Haiku | 계약이 고정돼 설계 판단이 없다. 저렴한 모델이 무너지는 건 판단이지 구현이 아니다 |
| `constitution-gate` | Sonnet | 체크리스트가 명확하다. 다만 "의미상 위반"은 더 작은 모델이 놓친다 |
| `contract-owner` | Opus · **쓰기 도구 없음** | 계약 변경은 전 모듈에 파급된다. 제안만 하고 적용은 사람이 |

**오케스트레이터는 코드를 읽지 않는다.** `spec/manifest.yaml` 한 파일만 읽고,
워커에게는 자기 행 + 계약 1개 + FR 1개만 준다.

### `contract-owner`가 실제로 값을 한 두 사례

1. **`FactPatch.confirmed` 제거** — 확정 필드를 PATCH로 받으면 클라이언트가 임의로
   확정 상태를 만들 수 있다. 에이전트는 이것을 *명세 드리프트*로 진단하고 제거를 제안했다.
   덧붙여 "확정 후 값을 고치면 확정이 무효여야 한다"는 미정의 지점까지 짚었다 —
   그대로 두면 "확정 → 금액 수정 → 미확인 값으로 문서 생성"이 열린다.
2. **facts 조회 경로 부재** — 확인 화면이 값을 읽을 방법이 추출 재호출뿐이었는데,
   그건 UPSERT라 **사용자 편집분을 덮는다.** 조회 계약 신설을 제안하면서
   "조회 추가는 UPSERT 결함을 가릴 뿐"이라는 잔여 결함도 함께 보고했다.

## 5. 검사는 스크립트가 먼저, LLM은 나중

저렴한 모델의 실패 모드는 예측 가능하고 대부분 코드로 잡힌다.

| 실패 유형 | 검출 | 비용 |
|---|---|---|
| 계약·envelope 위반 | `tsc --noEmit` + 런타임 `parse()` | 0 |
| 소유 경로 밖 수정 | PreToolUse 훅 (fail-closed) | 0 |
| 프롬프트 안의 법률 수치 | `gate:check` | 0 |
| 개인정보 패턴·폐기 용어 | `gate:check` | 0 |
| 원칙 위반(의미) | `constitution-gate` | 여기만 LLM |

`gate:check` 8종이 먼저 돌고, 통과한 diff에만 LLM 검사가 붙는다.
`constitution-gate`의 첫 동작은 검사가 아니라 **차단**이다 —
보호 경로를 건드린 diff는 LLM 호출 없이 사람에게 넘긴다.

## 6. 안전장치를 만드는 것과 작동하는 것은 다르다

훅을 만들어두고 "있으니 된다"고 넘어갈 뻔했다. 탐침을 심어 확인하니
**호출은 되는데 아무것도 막지 못하고 있었다** — 실행 환경이 주는 경로는 백슬래시인데
차단 패턴은 슬래시라 매치가 영원히 실패했다.

같은 계열의 함정을 세 번 만났다.

| 증상 | 원인 |
|---|---|
| manifest 자동 갱신이 조용히 안 됨 | Windows의 `python3`가 스토어 **스텁** — 존재 확인은 통과, 실행은 안 됨 |
| 팀원 clone 시 훅이 깨질 뻔 | CRLF 변환 (`.gitattributes`로 `*.sh` LF 고정) |
| 훅이 아무것도 못 막음 | 백슬래시 경로 vs 슬래시 패턴 |

전부 **"리눅스 가정이 Windows에서 조용히 무력화"**되는 부류다.
교훈은 하나 — **존재 확인이 아니라 실행 확인.**
그래서 검사 규칙을 고칠 때마다 *일부러 위반을 심어 잡히는지* 확인한다.

## 7. e2e가 미리 잡은 것들

`pnpm e2e`는 16단계 관통이자 **자기 증명 스크립트**다. 실제로 잡은 버그들:

- **증빙이 영원히 생성되지 않는 경합** — 폴링이 먼저 `COMPLETED`로 동기화하면
  아웃박스가 "전이 불가"로 판단해 증빙 생성을 건너뛰었다.
  "완료면 증빙이 있다"를 전이와 분리된 불변식으로 뺐다
- **웹훅 이벤트명이 실제와 달랐다** — 공식 문서 확인 결과 `document_completed`는
  존재하지 않는다(`document_all_signed`). 게다가 `document_signed`는
  "마지막 서명자 제외"라 완료가 아니다 — 그걸 완료로 처리했다면
  **마지막 서명 전에 증빙이 봉인**됐을 것이다
- **스케줄러가 GET으로 호출한다** — 실행을 POST에만 두면 배포해도
  리컨실러가 영원히 돌지 않는다
- **정책 거부가 장애로 집계됐다** — 게이트 차단이 실행 지표의 빨간 숫자로 읽혔다.
  두 테이블의 역할을 분리하고 회귀 방어를 넣었다
