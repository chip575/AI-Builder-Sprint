# 남기다 (NAMGIDA)

> 죽음이 구체화되는 사건을 겪었지만 아직 시간이 있는 사람이, 남기려는 마음을
> 대화로 정리하고 **법이 인정하는 방식으로만** 서명하며, 세션 주기와 무관하게
> 저장·관리·갱신하는 서비스.

- **마음** = 살아있는 유서(마음 유언) — 법적 효력이 없음을 명시하고 보관·전달
- **실행** = 기부·유산·자산 약정(전자서명) + 자필유언 필사 가이드

## 이 서비스가 다루는 문제

남기려는 결심은 의지가 없어서 사라지는 게 아니라 **절차의 마찰** 때문에 사라진다.
그래서 폼 대신 대화로 시작한다.

그런데 대화로 정리했다고 아무 문서에나 전자서명을 붙이면 안 된다 —
**자필증서 유언은 전자서명으로 효력이 생기지 않는다**(민법 §1060·1065·1066).
"AI가 유언장을 만들어 전자서명해 준다"는 아이디어는 법적으로 무효다.

우리는 이 사실을 숨기지 않고 **제품의 중심에 둔다.**

## 핵심 장치 — 법적 유효성 게이트

모든 문서 생성 요청은 게이트를 통과한다. 판정은 세 갈래다.

| 판정 | 의미 | 처리 |
|---|---|---|
| `ESIGN_OK` | 전자서명으로 효력 발생 | 서명 요청 → 증빙 보관 |
| `ESIGN_INVALID` | 전자서명해도 무효 | **서버가 차단** + 조문 인용 + 자필 필사 가이드로 라우팅 |
| `NON_BINDING` | 효력 없음이 의도된 문서 | 서명 없이 보관 |

차단은 **UI가 아니라 서버**가 한다. 버튼을 숨기는 건 눈속임이고 API 직접 호출로 드러난다.
게이트 판정 로직은 LLM이 아니라 순수 함수다 (`src/lib/rules/validity-gate.ts`).

**자필 유언 화면에는 서명 버튼이 존재하지 않는다.** 그 부재를 테스트가 지킨다 —
응답 키 검증과 화면 소스 검사 두 층위로.

## 다섯 가지 원칙

1. **AI는 묻고, 사람이 정한다** — AI 산출물은 `confirmed=false`로 태어나고,
   확인 버튼을 누르지 않으면 서버가 문서 생성을 거부한다
2. **유효하지 않은 문서는 만들지 않는다** — 게이트를 통과하지 못하면 대체 경로로
3. **모든 주장에는 근거가 붙는다** — 법률 수치는 LLM이 만들지 않는다.
   코드화된 룰 테이블에서만 나오고, 조문 ID와 갱신일자를 화면에 함께 노출한다
4. **거절 가능성을 항상 열어둔다** — 모든 화면에 "나중에 생각할래요".
   재촉 표현("지금", "빨리", "놓치기 전에")을 쓰지 않는다
5. **증빙은 서명 이후에도 살아있다** — 갱신·재검토·이행까지 추적한다

## 환경변수

`.env.example`을 `.env`로 복사해 필요한 것만 채우면 됩니다.
**하나도 안 채워도 앱은 완전히 동작합니다** — 채운 것만 실 연동으로 바뀝니다.

```bash
cp .env.example .env
```

### 모드 스위치 — 이것만 알면 됩니다

| 변수 | 값 | 뜻 |
|---|---|---|
| `UPSTAGE_MODE` | `mock`(기본) · `real` | `real`이면 Solar 실호출. **키가 없으면 조용히 mock으로 떨어지지 않고 실패합니다** |
| `MODUSIGN_MODE` | `mock`(기본) · `real` | `real`이면 모두싸인에 실제 서명 요청 |

DB는 스위치가 따로 없습니다 — `NEXT_PUBLIC_SUPABASE_URL`과
`SUPABASE_SERVICE_ROLE_KEY`가 **둘 다 있으면** Supabase로, 없으면 인메모리로 붙습니다.

### 전체 목록

| 변수 | 없으면 | 설명 |
|---|---|---|

## 검증

```bash
pnpm test         # 유닛·라우트 테스트
pnpm typecheck    # 계약 위반은 타입 에러가 된다
pnpm gate:check   # 프로젝트 불변식 9종 (법률 수치 위치·개인정보 패턴 등)
pnpm e2e          # 발화→서명→증빙 17단계 관통 (dev 서버 띄운 뒤, 키 없이)
```

`pnpm e2e`는 검산까지 확인한다 — 세액공제 276,000원, 답례품 한도 초과 거부,
동일 웹훅 5회 → 부수효과 1회, 유언 차단 + 조문 인용.

## 기술 구성

Next.js(App Router) · TypeScript · Zod · Tailwind · Supabase(RLS·트리거) ·
Upstage Solar / Document Parse / Information Extract · 모두싸인 전자서명

**어댑터 경계**로 외부 의존을 감쌌다 — `SignerPort`·`ExtractorPort`·`DocumentScannerPort`·
`StorePort`. mock과 real이 같은 인터페이스를 구현하고, 키가 없으면 mock으로 동작하되
**기동 로그 한 줄로 선언한다**(`[mode] DATA=… UPSTAGE=… MODUSIGN=…`).
조용히 폴백하지 않는다.

## AI를 어떻게 썼는가

**AI로 코드를 짠 게 아니라, AI가 코드를 짜도 무너지지 않는 구조를 짰다.**
설정 파일은 전부 이 저장소에 들어 있다 — `CLAUDE.md` · `AGENTS.md` · `.claude/`.

### 세 층으로 내려보냈다

| 층 | 무엇 | 어기면 |
|---|---|---|
| 서사·근거 | 헌법(`spec/00-constitution.md`) → 명세 → 계약 → 구현 | 사람이 잡는다 |
| 입출력 계약 | Zod 스키마 27개(`src/lib/contracts/`). 프론트·백이 같은 것을 import | `tsc`가 실패한다 |
| 작업·소유 경로 | `spec/manifest.yaml`에 사람별 담당 경로. 훅이 강제한다 | 훅이 차단한다 |

### 실제로 쓴 장치

| 파일 | 하는 일 |
|---|---|
| `CLAUDE.md` · `AGENTS.md` | 절대 규칙. "계약·룰 테이블·서명 URL을 고쳐야 하면 **멈추고 사람에게 보고**" |
| `.claude/settings.json` | 훅 등록 — `PreToolUse`(소유 경로 검사) · `SubagentStop`(작업표 갱신) |
| `.claude/scripts/check-ownership.sh` | 남의 담당 경로를 수정하려 하면 **파일 저장 자체를 막는다**(fail-closed) |
| `.claude/scripts/gate-check.sh` | 불변식 9종 — 프롬프트 속 법률 수치, 개인정보 패턴, 폐기 용어, 조문 신선도 |
| `.claude/agents/impl-worker.md` | 계약 하나·FR 하나만 받는 구현 담당. 설계 판단을 하지 않는다 |
| `.claude/agents/constitution-gate.md` | diff가 다섯 원칙을 어겼는지만 보는 검증 담당 |
| `.claude/agents/contract-owner.md` | 계약 변경 제안만 낸다. **쓰기 도구가 없다** — 적용은 사람이 한다 |

### 판단은 코드에, 문장만 AI에

법률 수치·게이트 판정·법정 문안·안내 문장은 전부 코드다. LLM은 문체와 초안까지만 한다.

그렇게 정한 이유는 실측이다. 모델에게 법률 문장을 맡겼더니 사인증여 약정을 두고
**"공증 절차를 마친 후부터 효력이 발생합니다"**라고 답했다 — 사망 시 효력이고 공증은
필요 없다. 유류분은 방향을 반대로 설명했다. 그래서 되돌렸다:

- 안내 문장은 `src/lib/ai/session/guide.ts`가 조문·확인일자와 함께 만든다
- 규칙이 못 잡은 질문만 모델이 **라벨을 고르고**, 문장은 여전히 코드가 낸다
  (`guide-classifier.ts`) — 법령 문장이 프롬프트에도 모델 출력에도 없다

### 막혔을 때 우회하지 않게 했다

훅이 소유 경로를 강제하니 워커는 남의 파일을 물리적으로 수정할 수 없다. 실제로 세 번
막혔고 세 번 다 커밋 없이 보고로 끝났다. 한 번은 **지시서 쪽이 틀렸다**는 것이 드러났다.

차단 검사는 **쌍으로 잰다** — 막혀야 할 것만 보면 "전부 막는 검사"와 구별되지 않는다.
실제로 훅이 워커의 *자기 경로*까지 막고 있었는데, 통과 케이스를 넣고서야 드러났다.
